# 五维评分标准与封顶规则

评分只来自证据。没测到 ≠ 没问题。源自 wai-play rater_v6 / scoring_standards 的口径沉淀。

## 五维与权重

| 维度 | 权重 | 评什么 | 证据来源 |
|------|------|--------|----------|
| task_flow 核心流程 | 0.24 | 能启动、目标明确、流程闭环、失败可重试、能通关 | verdict + trace 状态流转 |
| gameplay 核心玩法 | 0.26 | 核心循环成立、规则一致、操作响应、难度曲线 | trace 状态变化率 + 动作有效性 |
| ui_quality UI 视觉 | 0.20 | 可读性、层级、入口可发现、无遮挡 | 截图(LLM 基于状态与截图存在性推断,注明证据形式) |
| feedback 操作反馈 | 0.15 | **画面可见**反馈;API 数值变化不能单独给高分 | stagnation 指标 + console |
| technical_quality 技术稳定 | 0.15 | 无崩溃、无 console error、加载正常 | console_errors + pageerror |

## 计分规则

1. 每维 0–100,**无证据的维度记 null,不猜分**。
2. 总分 = Σ(维度分 × 权重) / Σ(已评维度权重)。
3. 已评权重 < 60% → 总分留空,报告写"证据覆盖不足,总分不评"。
4. 5 分制 = 百分制 / 20。

## 封顶(caps)规则 — 命中即取 min

| 条件 | cap |
|------|-----|
| 通关目标客观不可达(如跳跃高度不够越过必经障碍) | 45 |
| 必要操作不可用(核心动作无响应) | 50 |
| 严重技术问题(console error > 3 或崩溃) | 50 |
| 流程阻断/卡死(stagnation 终止) | 55 |
| critical 级问题存在 | 58 |
| major 级问题存在 | 68 |
| 未达 release 质量门(非全成功或有 console error) | 89 |

≥90 分需要:≥1 次成功 + 1 次 verification 复现 + 五维证据齐全 + 零 console error。

## 可信度(与游戏质量分离,单独展示)

| 等级 | 条件 |
|------|------|
| high | full_test API + 成功通关 + verification 复现 |
| medium | API 可用但未通关,或 limited API |
| low | black_box 黑盒模式(无结构化状态,胜负靠推断) |

注意:API 接入完整度本身不计入游戏质量分 —— 接了 API 不加分,没接不扣分,只影响可信度。

## 问题严重度定义

- **critical**:阻断通关(卡死、必经操作失效、目标不可达)
- **major**:显著损害体验但可绕过(反馈缺失、数值失衡、报错但可继续)
- **minor**:polish 层面(视觉不一致、提示不清)

Agent 自身操作失误(选错动作、超时)不是游戏问题,不进问题卡片、不影响评分。
